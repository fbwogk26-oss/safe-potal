## 규칙
자동화 작업(이메일 자동접수, 크론 잡 등)이 사람의 후속 확인/입력을 요구하는 레코드를 생성했을 때,
새로운 미니 확인 다이얼로그를 만들지 말고, 해당 데이터 타입에 이미 존재하는 전체 편집 다이얼로그를
자동으로 열어주는 큐(queue) 패턴을 사용한다.

**Why:** 사용자가 경량 팝업(제목/버튼만 있는 작은 확인창)을 명시적으로 거부하고 "너무 작고 내용이 없다"고
피드백한 적이 있음. 자동 등록된 항목이라도 결국 사람이 상세 내용(사진, 사유 등)을 확인/입력해야 하므로,
기존의 풍부한 편집 UI를 그대로 활용하는 것이 UX상 더 적합함.

**How to apply:**
- 자동화가 생성한 레코드 ID들을 배열 큐 상태로 쌓아둔다.
- useEffect로 큐 head에 대해 기존 "열기" 핸들러(예: openXxxDialog)를 호출해 자동으로 표시한다.
- 다이얼로그 저장/취소/닫기 시 큐 head를 pop하고 다음 항목이 있으면 이어서 자동으로 연다.
- 다이얼로그 안에는 "자동 접수되었습니다 (남은 N건)" 같은 배너를 넣어 큐 진행 상황을 알려준다.
- 자동 등록 시 여러 장의 사진 등 다중 첨부가 있다면, 미리보기 박스에만 넣지 말고 실제 편집 폼의
  해당 입력 섹션(예: "사진" 필드)에 직접 채워 넣어 편집 폼만으로 전체 정보를 다룰 수 있게 한다.
