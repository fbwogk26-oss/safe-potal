---
name: 장시간 열린 SPA에서 "오늘 날짜" 기본값이 고정되는 문제
description: useState(() => new Date()...) 처럼 마운트 시점에 한 번만 계산되는 날짜 기본값은 이후 날짜가 바뀌거나 새 데이터가 들어와도 갱신되지 않음
---

컴포넌트가 오래 떠 있는 SPA(사용자가 브라우저 탭을 계속 켜두는 대시보드/포털)에서 `useState(() => new Date().toISOString()...)` 같은 지연 초기화는 **마운트 시점에 딱 한 번만** 계산된다. 리렌더링이 일어나도 값이 갱신되지 않으므로, 기간 필터·다운로드 종료일 등 "오늘까지"를 의미하는 기본값이 실제로는 과거 날짜에 고정되어 최신 입력 데이터가 누락되는 것처럼 보인다.

**Why:** 실사용에서 "새 데이터를 입력하고 오늘 날짜까지 다운로드/미리보기 했는데 반영이 안 된다"는 버그 리포트의 실제 원인이 서버 로직이 아니라 프론트엔드에 고정된 stale 날짜 state였던 사례가 있었다 (AIS 일일 보고 메일 기간별 다운로드).

**How to apply:** 날짜 범위를 갖는 다이얼로그/패널을 열 때마다(`open` 상태가 true로 바뀌는 시점) `useEffect`로 시작일/종료일 state를 현재 날짜 기준으로 재계산해서 리셋하라. 서버 쪽에서도 "자동 스케줄 작업"과 "사용자가 수동으로 트리거하는 액션"의 기준일을 분리해서, 수동 액션은 최신 데이터를 포함하도록 기본값을 "오늘"로, 자동 스케줄은 기존 설계(예: "어제까지 집계")를 유지하는 패턴이 안전하다.
